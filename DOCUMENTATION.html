Storva — Setup & Customization Guide

Thank you for purchasing Storva. This guide takes you from zero to a live store, no prior Flutter or Supabase experience needed. Estimated time: 30–45 minutes.

2. Try it first (demo mode, 5 minutes)

The package runs immediately with sample data. No accounts, no setup:

cd storva
flutter pub get
flutter run -d chrome
  • Storefront opens automatically.
  • Admin panel: add #/admin to the URL (e.g. http://localhost:8080/#/admin). In demo mode it opens without a password so you can explore.

3. Create your Supabase backend (15 minutes)

Step 1. Go to supabase.com → Start your project → create a new project (any name, any region, save the database password it generates).
Step 2. In the left menu open SQL Editor → New query → open supabase/schema.sql from this package, copy its entire contents, paste, and press Run. This creates all tables, security rules, checkout functions, the image storage bucket and sample content.
Step 3. Open Authentication → Users → Add user. Enter your email and a strong password. This is your admin login — keep it private.
Step 4. Register that account as an admin. Back in the SQL Editor, run this with your admin email: 
insert into public.admins (user_id, email)
select id, email from auth.users
where email = 'you@yourstore.com';
Only accounts in public.admins can read orders or manage the store. A random self-registered account gets nothing.
Step 5. Recommended: open Authentication → Sign In / Up → Providers → Email and turn OFF Allow new users to sign up, so strangers cannot create accounts on your project at all.
Step 6. Open Project Settings → API. Copy the Project URL and the anon public key.

4. Connect the store to your backend (2 minutes)

Open lib/core/config.dart and fill in the marked fields:

static const String storeName = 'My Store';          // your brand
static const String currencySymbol = '\$';            // e.g. '\$', '€', 'EGP '
static const String whatsappNumber = '15550102299';  // digits only, or '' to hide
static const String supabaseUrl = 'https://xyzcompany.supabase.co';
static const String supabaseAnonKey = 'eyJhbGciOi...';

Run flutter run -d chrome again. The storefront now shows your database content, and #/admin asks for the admin login from Step 3.

Security note. The anon key is designed to be public — your data is protected by the Row Level Security policies and the public.admins allowlist in schema.sql. Never put the service_role key anywhere in this app.

Known limits, honestly: checkout has no rate limiting or captcha (scripted fake orders are possible — add a captcha Edge Function if this becomes a problem); admin login is email/password unless you enable MFA under Authentication settings; Supabase free projects pause after 1 week of inactivity and free orgs run at most 2 active projects — the store looks offline while paused until someone unpauses it from the dashboard. Upgrade to Pro for an always-on store.

5. Add your products

  1. Open #/admin and sign in.
  2. Products → Add product: name, description, price, optional old price (shows a sale badge), category, photo.
  3. Shipping: add the regions you deliver to and their prices. These appear in checkout.
  4. Coupons: generate single-use discount codes for promotions.
  5. Delete the sample products whenever you're ready (trash icon).

6. Put your store online

Any static web host works. Two easy options:

Netlify / Vercel: run flutter build web --release, then drag the build/web folder onto their dashboard.

GitHub Pages: push this project to a repository; the included .github/workflows/deploy.yml builds and publishes automatically. Set the correct --base-href inside it (usually /your-repo-name/).

8. How orders work

  1. Customer checks out (cash on delivery). Prices, discounts and shipping are recomputed by the database, so they can't be manipulated from the browser.
  2. The order appears in Admin → Orders as New.
  3. Call or WhatsApp the customer (button on the order) to confirm, then move the order through: New → Confirmed → Shipped → Delivered (or Cancelled).

9. Troubleshooting

SymptomFix
Storefront is empty after connecting SupabaseProducts exist but is_active off? Or schema.sql wasn't run. Check SQL Editor history.
"Wrong email or password" on admin loginCreate the user under Authentication → Users; confirm the email if confirmations are enabled (Authentication → Settings).
Checkout error when placing an orderMake sure the region selected exists in Shipping rates and is active.
Images don't uploadRe-run the storage section of schema.sql; the product-images bucket must exist and be public.
Blank page after deployingThe --base-href is wrong. It must match the URL path (e.g. /repo-name/ on GitHub Pages, / on Netlify).
